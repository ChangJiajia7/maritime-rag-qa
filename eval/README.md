# 评估集构建规范（80–100 条 QA）

- **一条 QA 六要素**：`id, split, question, answer, source_doc, source_loc`——`source_loc` 必须精确到条款号 / 通告期号 + 页码；**标不出出处的题一律不收**（防自欺，这是引用溯源验收的地基）。
- **split**：`train`（微调用，约 60%）/ `test`（只做评测，永不参与微调）。test 一旦泄漏进微调，微调前后对比作废。
- **答案规范**：答案必须是原文依据的改写，不引入原文没有的数字；每题标 1 个考点（术语消歧 / 条款查找 / 多条件交叉）。
- **数量底线**：test ≥ 30 条才谈得上 recall@k 的稳定性；不足时先补标注再谈微调。
- 模板见 `qa_eval_set.csv`，示例行用完删除。

## 标注流程建议

1. 通读语料 → 列高频考点（锚泊/号灯/避碰/报告制度…）→ 按考点配额出题，避免全集中在最容易标的部分。
2. 双查：每题标注后隔天自查一遍出处页码（冷手复核抓错最有效）。
3. 定稿冻结：test 部分定稿后不再改题面，只允许追加新题。
